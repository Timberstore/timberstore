# Checkout summary — preview 0.6.9

Base: `349c64f31ac7755d2d2bf81d75d376a1d735462d` (0.6.8); separate branch `feature/checkout-summary-v069`. Production/main/loader/tags unchanged.

## Implementation

- Steps 2/3 use Apollo's existing `.order-summary-top` as a separate beige product/method card. Only that card scrolls on desktop. No cloned products, prices, buttons or form controls, and no functional DOM moves.
- Native `.order-summary-bottom`, subsequent consents/legal controls and `.next-step` form one visually connected lower card, separated by 16 px from the upper card. Native form ownership and IDs remain unchanged. The lower CTA is outside the upper scroll region; the whole sidebar no longer scrolls internally.
- One guarded ResizeObserver measures the actual native lower content. Desktop sticky activates only if a useful upper region and the complete lower content fit below the existing 200 px header clearance, with 16 px viewport clearance. Small-height laptops fall back to ordinary page scroll. The independent upper list has a 55 vh limit on desktop; mobiles have natural page flow with no list cap or inner scroll. Default scroll chaining is retained.
- First cart step keeps its single summary card and gains a 28 px spacing above the primary CTA. Lower checkout actions have the same 28 px rhythm. Green/white CTA, desktop 67% width and mobile usable width remain unchanged.
- Product names are anthracite/600 with 1.4 line-height; metadata is secondary grey/600, unit 400; item totals are dark/700, right aligned. Existing `/ ks` and other unit format is retained. Shipping/payment names use medium weight, free prices stay green, and native final totals are the strongest amount (24 px).
- Only the word `SKLADOM` is uppercase/green in the sentence `Tovar SKLADOM expedujeme zvyčajne do 1–2 pracovných dní.` Other sentence text keeps its native style. Existing stock availability remains word-only green/uppercase, leaving counts unchanged. Central-warehouse word-only orange accent is preserved. Text synchronization is guarded/idempotent and reuses the existing lifecycle.
- No new API calls, duplicate listeners, order calculations or artificial page loader. The ResizeObserver is reused and reconnects only when native parts change; a single resize handler is bound with the module's existing listener guard.
