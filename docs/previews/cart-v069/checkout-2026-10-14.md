## Root cause and summary fix

The native Shoptet checkout bundle's `handleWithSidebar()` / `fixSidebar()` writes inline `position/top` and calls `$checkoutSidebar.removeAttr("style")` while scrolling. The old custom maximum-height variable was stored on that same element. Removing its style attribute erased the variable while the sticky class still referenced it with no fallback, so `max-height: var(...)` became invalid and the summary expanded.

- Store the limit on `.order-summary-top` itself, outside the native sidebar style-reset target. Always retain a bounded desktop fallback: `min(55vh, var(--ts-checkout-list-max, 55vh))`.
- Scope CSS position/top ownership to `#checkoutSidebar`, overriding only the native inline positioning conflict. Normal layouts are static; sticky is enabled only when the existing measured-fit check succeeds. Include the summary card margin in the viewport budget.
- The maximum is a viewport-dependent cap, never a forced content height. No wheel listeners or prevented events. Scroll chaining remains `auto`; mobile has no inner-scroll cap.
- Use flex order through the existing transparent native wrappers: native price recap first, then existing warnings/consents, then native actions, then the product/method summary. This changes visual order without moving or cloning functional elements. The two beige cards retain their shared width and gap; the price/actions frame remains connected.
