# Obnova Instagram galérie

## Incident z 24. novembra 2026

Produkčný Shoptet používa nemenný build `v0.7.7`. [Bundle](https://cdn.jsdelivr.net/gh/Timberstore/timberstore@v0.7.7/dist/timber.min.js) a [JSON](https://raw.githubusercontent.com/Timberstore/timberstore/main/data/instagram.json) vrátili HTTP 200. Oba manifestové endpointy, GitHub Raw aj jsDelivr, povoľujú CORS cez `Access-Control-Allow-Origin: *`. JSON obsahuje 16 príspevkov a dátum obnovy 13. novembra 2026. Všetkých 16 URL obrázkov vrátilo HTTP 404 s telom `text/html`. [Výsledky všetkých 16 GET požiadaviek](images.tsv). Obrázky sa načítavajú bežným elementom `img`, ktorý pre vykreslenie nevyžaduje CORS.

V Chromium na 1440 px a 390 px produkčný bundle vytvoril 16 položiek, no načítané obrázky mali `naturalWidth = 0`. Galéria ostala bez fotografií pred výberom cookies aj po prijatí alebo odmietnutí natívnym dialógom. Natívny slot Shoptetu bol prázdny aj po prijatí. Konzola v auditnom prostredí zaznamenala tiež chyby proxy `ERR_TUNNEL_CONNECTION_FAILED`. HTTP statusy fotografií sú z osobitných GET požiadaviek. [Produkčný frontend](https://www.timberstore.sk/)

Starý frontend držal globálny `feedRequest`, ale výsledok viazal na pôvodný blok. Pri oneskorenom vložení aj prázdneho natívneho bloku odstránil záložný blok, zahodil odpoveď a ďalší pokus už nespustil. Obnova v Pythone overovala formát URL v HTML bez overenia obsahu obrázkov. Úspešný beh s nezmeneným manifestom teda nepotvrdzoval dostupnosť galérie.

Dodatočná kontrola 25 unikátnych URL zo všetkých historických manifestov v Git repozitári vrátila HTTP 404 pri každej z nich.

## História obnovy

[Prehľad všetkých 99 behov](workflow-runs.tsv) pokrýva obdobie od 18. októbra do 24. novembra 2026. Z 88 úspešných behov 76 potvrdilo nezmenený feed, 9 zapísalo nový manifest a 3 boli overenia PR. Dva z troch logov pre PR GitHub neposkytol. Zo všetkých 11 neúspešných behov 10 skončilo odpoveďou HTTP 403 a posledný skončil odpoveďou HTTP 200 bez platných položiek. Rovnaký commit `3c82de3` mal úspechy aj oba typy zlyhaní. Logy neurčujú konkrétne pravidlo ochrany Shoptetu. [Posledný zápis dát](https://github.com/Timberstore/timberstore/actions/runs/43381886829) · [Neskorší úspech bez zápisu](https://github.com/Timberstore/timberstore/actions/runs/44996325611) · [HTTP 403](https://github.com/Timberstore/timberstore/actions/runs/45133988081) · [HTTP 200, 0 položiek](https://github.com/Timberstore/timberstore/actions/runs/45293452238)

## Prevádzka

Automatická obnova je vypnutá. Workflow spúšťa iba regresné testy pri zmenách v PR a nemá publikačný job ani prístup k Meta tokenu. Ak Timber Store neskôr schváli Meta API, znovu zapnite publikovanie na `main` a naplánujte jeden beh denne o 03:17 v časovom pásme Europe/Bratislava. Skript je pripravený čítať autorizované médiá. Pri výpadku, odmietnutí alebo menej ako šiestich dekódovateľných obrázkoch vypíše diagnostiku a ponechá existujúci manifest. [Syntax plánovania GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onschedule)

Manifest a JPEG kópie sa publikujú v tom istom commite. Cesty JPEG obsahujú hash ich obsahu. Staršie súbory sa pri obnove nemažú, aby zostali funkčné aj staršie verzie manifestu v cache. Primárna distribúcia je z GitHub Raw a sekundárna z jsDelivr. Oba endpointy majú verejné čítanie. Prvý zápis ide cez kontrolovaný import a PR. Prehliadač uprednostní aspoň šesť dekódovaných položiek z jedného manifestu. Ak ich je menej, použije zdroj s najväčším počtom použiteľných uložených fotografií alebo dostupnú natívnu galériu. Doplnok nečíta ani nezapisuje stav súhlasu a neposiela prihlasovacie údaje v požiadavke na manifest. Na Instagram vedie odkaz z fotografie.

V GitHube publikujte iba médiá, ku ktorým má Timber Store právo na verejnú redistribúciu. Verejný Git uchováva históriu. Pri raste objemu alebo požiadavke na jednoduchšie odstraňovanie súborov je cieľom hosting pod kontrolou Timber Store, napríklad statické úložisko na `media.timberstore.sk` s HTTPS a verziovaním. Verejnosti stačí čítanie a publikačnej identite zápis len do prefixu galérie. Pri takom presune treba zmeniť schválené originy, ponechať staršie generácie dostupné počas životnosti cache a publikovať manifest až po overení obrázkov.

## Prvé naplnenie a nasadenie

1. Po budúcom schválení automatickej obnovy autorizujte v Meta aplikácii profesionálny účet `@timberstore.sk` cez **Instagram API with Instagram Login** a oprávnenie `instagram_business_basic`. Použite podporovanú verziu Graph API vybranú v aplikácii. Nastavte GitHub Actions secret `META_INSTAGRAM_TOKEN` a Actions variable `META_INSTAGRAM_API_VERSION`, napríklad `v27.0`, ak ju aplikácia podporuje. Otvorte obnovu tokenu pred vypršaním platnosti podľa Meta a aktualizujte secret. Uistite sa, že pravidlá vetvy povoľujú schválený zápis publikačnej identity. [Meta Instagram Login](https://developers.facebook.com/docs/instagram/platform/instagram-api/changelog/) · [Referenčné polia médií](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/v21.0/)
2. Na prvý snapshot bez Meta API importujte minimálne šesť originálov s ich skutočnými permalinkmi. Pri importe pripravte manifest s poľom `posts` a položkami s kľúčmi `url`, `image` (názov súboru pri manifeste) a `alt`. Spustite `python scripts/refresh-instagram.py --import-manifest /cesta/manifest.json` v prostredí s Pillow a do PR pridajte iba vygenerovaný `data/instagram.json` a `data/instagram-media/`. Pôvodný manifest z 13. novembra obsahuje odkazy, ktorých súbory už server neposkytuje.
3. Po publikovaní sady fotografií overte HTTP 200, typ JPEG a dekódovanie všetkých zverejnených súborov. Na produkčnej doméne použite existujúci náhľad `?ts_preview=<nemenný commit SHA>` a overte šesť fotografií pri šírke 1440 px, šípky, mobilné posúvanie, permalinky a režimy natívneho dialógu cookies. Zopakujte s nefunkčným primárnym endpointom v izolovanom prehliadači. Náhľad ukončíte cez `?ts_preview=off`.
4. Po schválení nastavte v Shoptet loaderi `PROD` na schválený nemenný tag alebo commit. Zopakujte kontrolu v novej relácii bez náhľadového cookie. Rollback loadera použije predchádzajúci nemenný build. Ten nepodporuje relatívne cesty archívu, takže rollback pri tomto incidente slúži na obnovenie ostatných funkcií obchodu. Zachovajte archív fotografií aj manifest.
